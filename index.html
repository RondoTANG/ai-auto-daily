近期研究：DeepSeek dsh-superagent 研究原型

问题与能力：DeepSeek 公开仓库以 DeepSeek Harness 插件方式实现面向单一 GitHub 仓库的事件驱动编码智能体，监听 GitHub、可选飞书，按获准请求或规则创建工作项，在独立会话和目录执行，向原会话回复；面板展示需要人工处理的事项。11 月 1 日已有公开报道，原始提交时间未核实，不计入 24 小时新增。仓库称研究代码仅供参考，不是正式产品，也不等同于内部或论文实现。

业务场景与差异：可研究将车企内部工单或知识运营需求接入受控开发流程；相比聊天窗口一次性应答，强调事件入口、工作项状态和人工注意力管理。其 GitHub 单仓定位不等于现成的车企多智能体平台。

成熟度：有源码、配置与测试，未独立运行，未核实车企生产案例，不建议接生产仓库。

部署与边界：适合隔离自建试验；官方 setup 要求 Node.js 22.19+ 或 24+、pnpm、git 2.32+、tmux、Python 3.8+、GitHub CLI 2.48+、兼容版本 DeepSeek Harness 和模型服务；飞书需另配应用。使用测试账号、测试仓库及最小权限；模型或外部系统可能接收代码及消息，需检查出网、凭据、触发名单与审计。

成本和许可：MIT；模型调用、运行主机和相关服务另计，单价待核。无正式 release，具体提交日期待核。

试点：仅限隔离验证。构造 30 个模拟 issue（含 10 个未授权请求），统计正确触发与拦截、重复任务率、人工审核时间、单任务成本；目标未授权执行为 0，所有代码变更经人工审核，不自动合并。

近期研究：Playwright MCP v0.0.84 浏览器会话隔离

更新：官方 10 月 31 日 release 支持同一浏览器中以隔离 context 区分 cookie 与存储；可掩盖工具响应中的指定 URL 参数，但官方明确这只是便利功能而非安全机制。与共用登录上下文相比，可更方便进行多账号自动化测试，发布时间时区待核。

场景与成熟度：可用于经销商门户的测试账号隔离与登录流程验证；有公开版本和源码，本次未实测。以本地 MCP 服务接入，运行依赖 Node 与浏览器，版本限制以项目文档为准；开源许可、资源消耗与商用限制以仓库 LICENSE 与部署环境为准，具体费用待确认。

试点：用两个测试账号执行 50 次跨账号门户测试，检查 cookie 泄漏次数、越权页面访问和任务成功率；目标串号为 0，并验证日志不包含敏感参数。不得把 context 隔离视为完整安全边界。
