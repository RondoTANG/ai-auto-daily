AWS 汇总：将已有流程暴露为智能体工具

发生了什么：AWS 11 月 2 日周报回顾上周更新：AgentCore Gateway 通过 MCP 将已有 Step Functions 工作流暴露给智能体；Standard 和 Express 工作流可作为目标并查询执行。原功能上周上线，非 11 月 2 日新发布。

为什么重要（分析）：车企售后预约、退款或审批可以让模型决定何时调用，而固定资格校验、人工审批与写入顺序继续由已有流程执行。须在网关之外设计调用者权限、幂等和敏感操作审批。

继续跟踪：各区域可用性、每单编排成本、越权调用拦截率、超时后重复写入和人工接管比例；标准收费以 AWS 具体价目为准。

值得关注的 AI 新项目

近期值得研究（非过去 24 小时新增）：GitHub Agentic Workflows v1.0.1

问题与更新：GitHub 11 月 2 日周报回顾 10 月 27 日发布的 v1.0.1，提到更安全的 PR 输出、可选 actions-lock 集成和诊断改进；后续合入项包括 MCP HTTP 认证及限制上传大小。具体能力是否已进入稳定发布版须逐项对照版本。

场景及成熟度：可作为车企软件仓库中需求整理、问题分类和待人工审核改动的研究对象；有公开仓库及发行版，本次未运行、未核实车企生产案例。与自由执行的编码代理相比，可研究 GitHub 工作流与受限输出结合的方式。

部署、边界和成本：在自己的 GitHub 仓库和 Actions 环境配置，需 GitHub 权限与兼容的模型服务；具体依赖版本待核。源码可能发送给选定模型服务，须配置最小权限、敏感信息过滤和人工审批。许可证及 Actions/模型费用按所选版本和套餐确认，具体金额待核；不是完整离线私有部署方案。

试点：限测试仓库，用 30 条模拟 issue，其中 10 条包含越权或提示注入指令；比较人工处理时间、分类准确率、未授权写入次数与每条成本。目标未授权写入为 0，所有 PR 人工审核。

产品优先级

优先将售后业务中的资格校验、审批、幂等与审计固化在既有流程，再开放受限工具调用；依据是模型适合处理意图和参数，而关键交易链路需要稳定、可追溯的执行。
